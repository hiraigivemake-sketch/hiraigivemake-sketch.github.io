GitHubで公開する手順

一度だけ設定すれば、あとは 編集して「送る」を押すだけ でホームページが自動更新されるようになります。所要時間は30分ほど。難しい入力はありません。

できるようになること

・編集内容が自動でホームページに反映される（1〜2分）
・いつ誰が何を変えたか、すべて記録に残る
・まちがえても、以前の状態にいつでも戻せる
・複数のパソコンから編集できる（同時編集も安全）

安心してください。この作業をしても、いま公開中のホームページ（STUDIO版）には一切影響しません。新しいほうが問題なく動くのを確認してから、あとで切り替えます。

ステップ1：準備（初回だけ）

1

GitHubのアカウントを作る

github.com/signup を開き、メールアドレス・パスワード・ユーザー名を登録します（無料）。

ユーザー名は後でホームページのアドレスに使われます。kuricare や giveandmake のような、事業所に関係する短い英数字にしておくと分かりやすいです。

※ 登録したメールアドレスに確認メールが届くので、リンクを押して認証してください。

2

GitHub Desktop をインストールする

desktop.github.com から無料アプリをダウンロードして、アプリケーションフォルダに入れます。

起動したら Sign in to GitHub.com を押し、ステップ1で作ったアカウントでログインします。ブラウザが開くので Authorize を押してください。

※ 名前とメールアドレスを聞かれたら、そのまま Finish で進んで大丈夫です。

ステップ2：フォルダをGitHubに登録する

3

kuricare-site を GitHub Desktop に読み込む

GitHub Desktop のメニューから File → Add Local Repository… を選び、デスクトップの kuricare-site フォルダを選びます。

左側にファイルの一覧がずらっと表示されれば成功です。

4

最初の記録（コミット）をする

画面左下の入力欄に 最初の登録 と入力し、青い Commit to main ボタンを押します。

※ 「コミット」は「ここまでの状態を記録する」という意味です。写真を撮って残すようなイメージです。

5

GitHubに公開（アップロード）する

画面上部の Publish repository を押します。設定画面が出るので、次のようにします。

Nameユーザー名.github.io
ステップ1で決めたユーザー名を使います。例：ユーザー名が kuricare なら kuricare.github.io
Description空欄のままでかまいません
Keep this code privateチェックを外す（公開にする）

最後に Publish repository を押します。40MBほどあるので、1〜3分かかります。

名前は必ず「ユーザー名.github.io」にしてください。別の名前にすると、ホームページのアドレスが1段深くなり、デザインが崩れてしまいます。
また、無料でホームページを公開するには 公開（Public） の設定が必要です。載せているのは元々ホームページで公開している内容なので、問題ありません。

ステップ3：公開の設定を切り替える

ここがいちばん間違えやすい場所です。GitHubは初期設定のままだと、ホームページではなく「説明書」のページを公開してしまいます。下の手順で切り替えてください。

6

GitHubのページを開く

GitHub Desktop の画面の右側にある View on GitHub というボタンを押します。ブラウザ（Chrome や Safari）が開きます。

※ すでにブラウザで開いている場合は、そのままで大丈夫です。

7

「Settings」を押す

画面の上のほうに、文字が横一列に並んでいます。

Code　Issues　Pull requests　Actions　Projects　Wiki　Security　Insights　Settings

このうちいちばん右にある「Settings」をクリックしてください。歯車のマークが付いています。

8

左のメニューから「Pages」を探す

画面の左側に、メニューが縦に長く並びます。マウスで下のほうへスクロールすると、「Code and automation」というグループの中に Pages があります。これをクリックします。

※ 見つからないときは、キーボードの ⌘ + F を押して「Pages」と入力すると探せます。

9

「Source」を切り替える ← ここが本番

真ん中に Build and deployment という見出しがあります。そのすぐ下の Source という欄に、こう書かれた箱があります。

Deploy from a branch

この箱をクリックすると、選択肢が2つ出ます。下の GitHub Actions を選んでください。

保存ボタンはありません。選んだ瞬間に設定が変わります。画面が少し変化すれば成功です。

10

もう一度だけ、公開の作業を動かす

設定を変えただけでは、ホームページはまだ切り替わりません。もう一度だけ作業を動かします。

  1. 画面上部の Actions をクリック
  2. 左側の一覧から サイトを公開する をクリック
  3. 右側に出てくる 最初の登録 という行をクリック
  4. 開いた画面の右上にある Re-run all jobs ボタンを押す
  5. 確認の小窓が出たら、もう一度 Re-run jobs を押す

黄色い丸●が回り始めます。2〜3分待って緑のチェック✓になれば完成です。

11

ホームページを見る

ブラウザで https://hiraigivemake-sketch.github.io/ を開いてください。

オレンジ色のクリケアのホームページが表示されれば成功です。

※ 白い画面に黒い文字だけ、または「クリケア訪問看護ステーション ホームページ」という見出しの説明書が出る場合は、ステップ9がまだ反映されていません。3分ほど待って再読み込み（⌘+R）してみてください。

これからの使い方

覚えることは1つだけです。

ホームページを直したら、⑥ 変更をGitHubに送る をダブルクリックする。
それだけで、1〜2分後にインターネット上のホームページが新しくなります。

A

文章や写真を直したいとき

  1. ① 編集をはじめる をダブルクリック
  2. ブラウザの編集画面で直して、下の 保存する を押す
  3. 右上の サイトを見る で仕上がりを確認
  4. 編集画面と黒い画面を閉じる
  5. ⑥ 変更をGitHubに送る をダブルクリック

黒い画面に「✅ 送信しました」と出れば完了です。1〜2分後にホームページが新しくなります。

※ ⑥は送る前に自動で点検します。リンク切れなどがあると送信を止めて教えてくれるので、壊れたものが公開される心配はありません。

B

Claude Code に直してもらったとき

「トップの文章を変えて」「スタッフを1人増やして」などと Claude Code に頼んだ場合も、やることは同じです。

  1. Claude Code が直し終わるのを待つ
  2. ② ホームページを見る で仕上がりを確認
  3. ⑥ 変更をGitHubに送る をダブルクリック

どこが変わったのか目で確かめたいときは、GitHub Desktop を開いてください。左側に変わったファイル、右側に「赤＝消えた文字」「緑＝増えた文字」が色分けで表示されます。確認したら、左下に一言（例：トップの文章を修正）を入れて Commit to main → 上の Push origin を押します。⑥ を押すのと同じ結果になります。

C

まちがえて公開してしまったとき

あわてなくて大丈夫です。すべての変更が記録に残っているので、いつでも戻せます。

  1. GitHub Desktop を開く
  2. 左上の History タブをクリック
  3. 戻したい記録（日時と一言が並んでいます）を右クリック
  4. Revert changes in commit を選ぶ
  5. 上の Push origin を押す

1〜2分でホームページが元の状態に戻ります。

他のパソコンでも編集する

GitHubに置いてあるので、何台のパソコンからでも編集できます。
USBメモリで持ち運ぶ必要はありません。

D

2台目のパソコンでの、はじめの準備（1回だけ）

  1. そのパソコンに GitHub Desktop をインストールし、同じアカウントでログイン
  2. メニューの File → Clone repository… を選ぶ
  3. 一覧から hiraigivemake-sketch.github.io を選ぶ
  4. 保存先を「デスクトップ」にして Clone を押す

ダウンロードが終わると、1台目とまったく同じフォルダができます。① 編集をはじめる などのボタンもそのまま入っています。

Windows のパソコンの場合

Macは ① 編集をはじめる.command をそのまま使いますが、Windowsではこの形式のファイルが動きません。かわりに まったく同じ働きをするファイル を Windows用 というフォルダに入れてあります。

つまり、Windowsの人は「Windows用」フォルダを開いて、その中の①〜⑥をダブルクリックするだけです。使い方はMacと同じです。

ただし、はじめの1回だけ Python というソフトを入れる必要があります（Macには最初から入っていますが、Windowsには入っていないため）。手順は下の章をご覧ください。

Windowsのパソコンで使う準備

Macだけで使う場合は、この章は読み飛ばして大丈夫です。
Windowsのパソコンでも編集したいときだけ、はじめに1回だけ必要な作業です。5分ほどで終わります。

なぜ必要なの？

このホームページは「Python（パイソン）」というソフトを使って組み立てています。Macには最初から入っていますが、Windowsには入っていません。そのため、Windowsのパソコンでは一度だけ入れてあげる必要があります。

Pythonは裏方のソフトなので、入れたあとに開いたり操作したりすることはありません。入れっぱなしでOKです。

W1

「Microsoft Store」を開く

Microsoft Store は、Windowsに最初から入っているアプリのお店です。買い物袋のようなアイコンをしています。

  1. 画面のいちばん下（または左下）にある Windowsのマーク をクリック
  2. そのまま microsoft store とキーボードで入力
  3. いちばん上に出てくる Microsoft Store をクリック
W2

「Python 3」を探して入れる

  1. Microsoft Store の上のほうにある検索欄（虫めがねマーク）をクリック
  2. Python 3 と入力して Enter キーを押す
  3. 一覧に Python 3.12 のようなものが並びます。数字がいちばん大きいものをクリック
    （3.11 でも 3.13 でも問題ありません）
  4. 青い 入手 または インストール ボタンを押す
  5. 「ダウンロード中」→「開く」に変わったら完了です

「開く」は押さなくて大丈夫です。そのままウィンドウを閉じてください。設定する項目はありません。

※ 途中で Microsoft アカウントのサインインを求められたら、「後で」「スキップ」などを押して閉じても、インストールは進みます。

W3

「Windows用」フォルダの中を使う

準備はこれで終わりです。あとは、フォルダの中の Windows用 を開いてください。

中に、Macとまったく同じ①〜⑥のファイルが入っています。

  • ① 編集をはじめる.bat … 文章や写真を直す
  • ② ホームページを見る.bat … できあがりを見る
  • ③ 点検する.bat … リンク切れなどをチェック
  • ④ バックアップを取る.bat … まちがえたとき用に保存
  • ⑤ 共有用にまとめる.bat … 他のPCへ渡すZIPを作る
  • ⑥ 変更をGitHubに送る.bat … 直した内容を公開する

使い方はMacとまったく同じで、ダブルクリックするだけです。

※ _python.bat は他のファイルが内部で使うものです。ダブルクリックしないでください。

「WindowsによってPCが保護されました」と青い画面が出たら

詳細情報 をクリック → 下に出てくる 実行 を押してください。自分たちで作ったファイルなので問題ありません。初回だけ出ます。

Pythonが入っているか分からないとき

とりあえず ③ 点検する.bat をダブルクリックしてみてください。入っていなければ、黒い画面にインストール手順が日本語で表示されます。入っていれば点検結果が出ます。

E

2台目以降で編集するときの、大事なルール

編集を始める前に、必ず最新の状態にしてください。

  1. GitHub Desktop を開く
  2. 上の Fetch origin を押す
  3. Pull origin に変わったら、それも押す
  4. その後に ① 編集をはじめる で編集する

これをしないと、他のパソコンでの変更が消えることがあります。
「編集の前に Fetch と Pull」──これだけ習慣にしてください。
また、2人が同時に編集するのは避けてください。「いまから触ります」と一声かけるルールにしておくと安全です。

もし「Conflict（衝突）」と出たら

2人が同じ場所を同時に直してしまったときに出ます。自分で直そうとせず、そのまま Claude Code に「GitHub Desktop で Conflict と出た」と伝えてください。安全に解決します。

最後の仕上げ：独自ドメインへの切り替え

ここまでで ユーザー名.github.io という仮のアドレスで公開されています。
しばらく（1〜2週間）使ってみて問題がなければ、本来のアドレス giveandmake-c.com に切り替えます。

切り替えの流れ（このときは相談してください）

1. GitHub側で独自ドメインを登録する
2. ドメインを管理している会社の画面で、向き先をGitHubに変更する
3. 反映を確認してから、STUDIOを解約する

2番はドメインを買った会社（お名前.com、ムームードメインなど）の管理画面での作業になります。どこで取得したかが分かれば、Claude Codeが手順をご案内します。

切り替えるまで、STUDIOは解約しないでください。切り替え後に問題が起きても、すぐ元に戻せるようにしておくためです。

困ったとき

Publish repository が押せない／エラーが出る
先に「Commit to main」を押しているか確認してください。1回も記録していないと公開できません。
アップロードがすごく遅い
写真が480枚ほどあるため、初回だけ数分かかります。2回目からは変更した分だけなので数秒です。
Settings に Pages が見つからない
リポジトリが非公開（Private）になっている可能性があります。Settings のいちばん下 Change repository visibility から公開（Public）に変更してください。
Actions が赤い×になった
×を押すと、どこで止まったかが表示されます。その画面をスクリーンショットするか、赤い文字をコピーして Claude Code に伝えてください。
ホームページではなく「説明書」のページが出る
ステップ9の設定（Source を GitHub Actions に変更）がまだの可能性があります。Actions の一覧に pages-build-deployment という項目があれば、それが原因です。ステップ9と10をやり直してください。
ページは出るが、文字だけで見た目が崩れている
リポジトリ名が ユーザー名.github.io になっていない可能性が高いです。Settings の Repository name から名前を変更してください。
GitHubは有料ですか
この使い方であれば無料です。公開リポジトリのホームページ公開機能（GitHub Pages）と自動更新（Actions）は、どちらも無料枠で足ります。
