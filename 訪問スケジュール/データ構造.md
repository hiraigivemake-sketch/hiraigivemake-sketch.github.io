# 訪問スケジュール データ構造 v1

単一HTML（`訪問スケジュール.html`）に内蔵するデータ層の仕様。画面はまだ無く、HTMLを開くとこの仕様どおりに動くかのセルフテストが走る。

## 方針

- 保存先は `localStorage` の1キー `houmon_schedule_db`。中身は1つのJSON。
- 日付は `YYYY-MM-DD`、時刻は `HH:MM`（24時間、`24:00` は終了時刻のみ可）。内部では必ずこの形式に正規化する。
- マスタ（利用者・スタッフ・計画）は物理削除せず `archived: true` で隠す。過去月の訪問が壊れない。
- 他レコードへの参照は名前でなく `id` で持つ。保存前に参照整合性を検証し、通らないデータは保存しない。
- `id` は「接頭辞_時刻(36進)＋連番(2桁)＋乱数(4桁)」。同一ミリ秒内に大量生成しても連番で衝突しない。
- 個人情報は最小限。被保険者番号・住所の番地・電話は持たない。表示には `displayName`（略称）を優先する。
- サンプルデータは架空の「利用者A」「看護 太郎」のみ。実名は入れない。

## Plan（訪問計画・週パターン）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `pl_` で始まる |
| `patientId` | string | ○ | |
| `serviceType` | enum | ○ | `nursing` / `rehab` |
| `durationMin` | 整数 | ○ | 1〜600。開始＋所要が翌日にまたがる値は不可 |
| `dow` | 0〜6 | ○ | 曜日 |
| `start` | HH:MM | ○ | |
| `staffIds` | string[] | ○ | 既定の担当 0〜2名。空なら未割当で展開 |
| `recurrence` | object | ○ | `kind`: `weekly` 毎週 / `biweekly` 隔週（`anchorDate` 必須。基準日以降で最初にその曜日になる日を起点に2週おき）/ `weeksOfMonth` 第N週（`weeksOfMonth: [1,3]` など 1〜5） |
| `period` | object | ○ | `from` / `to`。計画の有効期間 |
| `archived` / `note` / `createdAt` / `updatedAt` | | | |

`rules.expandPlan(db, plan, year, month)` が月展開を行い、`{ visits, skipped }` を返す。`visits` は未保存の Visit。`skipped` は見送った日と理由（`patientStatus` 入院等 / `holiday` 休日 / `exists` 展開済み / `patientArchived` 利用者が無効）。

`rules.expandMonth(db, year, month)` は有効な全計画を展開して DB に追加し、`{ added, skipped }` を返す（`skipped` には `planId` 付き）。同じ月に何度実行しても展開済みの日は重複しない。月表示の「計画を展開」ボタンはこれを呼ぶ。展開時、無効化したスタッフは担当から外して未割当にする。

`rules.checkPlanRules(db, plan)` は計画そのものの制約を判定する。`roleMismatch`（1人目の職種が種別に合わない）、`ngStaff`、`roleNotAllowed`、`needsTwoStaff`、`staffArchived`、`noStaff`、`noPatient` は保存をブロックし、`staffUnavailable`（その曜日・時間に勤務枠がない）と `patientArchived` は警告。日付に依存する判定（入院・指示書・重複）は展開後の訪問側で行う。

## Visit（訪問）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `v_` で始まる |
| `date` | YYYY-MM-DD | ○ | |
| `start` / `end` | HH:MM | ○ | `end` > `start`。日またぎ不可 |
| `patientId` | string | ○ | |
| `staffIds` | string[] | ○ | 0〜2名、重複不可。2名=複数名訪問 |
| `serviceType` | enum | ○ | `nursing` / `rehab` |
| `planId` | string/null | | 計画から展開した場合の元計画。`origin: plan` なら必須 |
| `origin` | enum | ○ | `plan` 計画から展開 / `manual` 手入力 / `transfer` 振替 |
| `status` | enum | ○ | `planned` 予定 / `confirmed` 確定 / `done` 実施 / `cancelled` キャンセル / `transferred` 振替元 |
| `cancelReason` | enum/null | 条件付 | `cancelled` のとき必須、それ以外は null。`patient` / `hospital` / `office` / `weather` / `holiday` / `other` |
| `transferredToId` | string/null | 条件付 | `transferred` のとき必須（振替先） |
| `transferredFromId` | string/null | 条件付 | `origin: transfer` のとき必須（振替元）。振替元と振替先は互いに参照し合う。片方だけでは検証エラー |
| `flags` | object | ○ | `emergency` 緊急訪問 / `training` 研修同行（複数名加算の対象外） |
| `actual` | object/null | 条件付 | `{ start, end }`。`done` のとき必須 |
| `note` / `createdAt` / `updatedAt` | | | |

保存しない派生値: 所要時間、時間帯区分（開始時刻で判定。22:00〜06:00 深夜、06:00〜08:00 と 18:00〜22:00 夜間・早朝、それ以外 日中）、長時間（90分超）、複数名（2名かつ研修でない）。加算判定はこれらから後工程で行う。

### ステータス遷移

| 現在 | 変更できる先 |
|---|---|
| planned | confirmed, done, cancelled, transferred |
| confirmed | planned, done, cancelled, transferred |
| done | confirmed（実施の取り消し） |
| cancelled | planned（キャンセルの取り消し） |
| transferred | なし（戻すには振替先を削除する） |

遷移は `rules.changeVisitStatus` と `repo.visits.setStatus` だけが行う。表に無い遷移は例外になる。

### 振替

`repo.visits.transfer(db, id, { date, start, end?, staffIds? })` が、元を `transferred` にし、新しい訪問を `origin: transfer` で追加し、双方向参照を同時に作る。振替で参照されている訪問は `remove` できない。

## Holiday（休日）

`{ date, name, kind }`。`kind` は `national` 祝日 / `office` 事業所休業日。同じ日付・種別の重複は不可。

## HistoryEntry（変更履歴）

`{ at, action, entity, entityId, before?, after? }`。`action` は `add` / `update` / `status` / `transfer` / `remove`。リポジトリ経由の変更が自動で積まれる。

## ハード制約チェック

`rules.checkVisitRules(db, visit)` が `[{ code, msg }]` を返す。空なら保存可。画面側はこれをブロック条件に使う。

| code | 内容 |
|---|---|
| `patientStatus` | 利用者がその日 active でない（入院・休止・契約外） |
| `noInstruction` | その日に有効な指示書がない |
| `roleMismatch` | 1人目の担当の職種がサービス種別に合わない |
| `staffUnavailable` | 担当がその時間帯に勤務可能枠を持たない、または在籍期間外 |
| `ngStaff` | 利用者のNG担当 |
| `roleNotAllowed` | 利用者の対応可能職種に含まれない |
| `needsTwoStaff` | 2名訪問必須なのに1名以下 |
| `staffOverlap` | 担当が同日同時刻に別の訪問を持つ（キャンセル・振替元は除く） |
| `patientOverlap` | 利用者が同日同時刻に別の訪問を持つ |
| `staffArchived` | 担当が無効化されている |

医療保険の週3日制限や介護の計画回数超過は、月単位の集計が必要なので次の段階（ルール層の拡張）で足す。

## 保存・読込

- `store.load(localStorage)` → `{ db, errors, fresh, backupKey }`。保存が無ければ空DB。JSONが壊れていれば消さずに `houmon_schedule_db_broken_<時刻>` へ退避して空DBで起動し、`errors` に理由を入れる。
- `store.save(db, localStorage)` → 検証に通らなければ保存せず `{ ok: false, errors }`。通れば `updatedAt` を更新して保存。4MBを超えると `warn` を返す。
- `store.parseDb(text)` → ファイル読込用。移行と検証を通した結果を返す。
- `store.migrate(raw)` → `schemaVersion` が古ければ順に変換、新しければ例外。欠けた配列や設定は既定値で補う。

## 画面（日・週・月）

画面のコードは `<script id="vs-app">` にあり、DOM を扱うのはここだけ。データの変更は必ず `VS.repo` と `VS.store` を通す。

| 表示 | 構成 | 操作 |
|---|---|---|
| 日 | 縦が時間軸（設定の範囲。はみ出す訪問があれば自動で広がる）、横がスタッフ列＋未割当列。同じ列で時間が重なる訪問は横に並ぶ | 空き枠クリックで追加（時刻は刻み単位に補完、担当は列のスタッフ）。ブロッククリックで編集 |
| 週 | 列が7日（設定の開始曜日から）、行がスタッフ（＋未割当）または利用者。行末に件数と合計時間 | セルの「＋」で追加（日付と行の担当/利用者を補完）。チップクリックで編集。日付クリックで日表示へ |
| 月 | カレンダー。1マス4件まで表示し、超えた分は「他 n 件」 | 「計画を展開」で有効な計画をその月に一括作成。日番号クリックで日表示へ |

共通: フィルタ（スタッフ / 未割当のみ / 利用者 / 種別 / キャンセル・振替元の表示）、集計バー（件数・合計時間・未割当・重複）、今日・休日・休業日の色分け。担当または利用者の時間が重なる訪問は赤枠で示す。

### 訪問の編集モーダル

- 項目: 日付、開始、終了、利用者、種別、担当1、担当2（複数名訪問）、緊急、研修同行、備考。実施済みは実績時刻も編集できる。
- 保存時の判定: まず項目の検証（`validate.visit`）、次に `rules.checkVisitRules`。**ブロック**（保存不可）は利用者の状態（入院・休止・契約外）、職種不一致、NG担当、対応可能職種外、2名必須、担当の時間重複、利用者の時間重複、担当の無効化。**警告**（保存は可）は勤務枠外と指示書なし。勤務枠は②勤務表ができるまで標準パターンしか持てず、指示書は更新待ちのまま翌月の予定を組む運用があるため、どちらも警告にとどめている。
- ステータスの操作: ステータス遷移表どおりのボタンだけを出す。キャンセルは理由を選んで確定、実施は実績時刻を入れて確定、振替は振替先の日付・開始時刻を入れて確定（担当を引き継ぐかを選べる）。振替先の保存前にも制約を判定し、ブロックなら元に戻す。
- 振替元は編集・削除できず、振替先へのリンクだけを出す。
- 削除は確認の上で物理削除。振替で参照されている訪問は削除できない。

### 保存と復元

- 変更のたびに `store.save` で保存する。DB 全体の検証に通らなければ保存せず、直前に保存した状態へ読み直す。
- 画面の設定（表示、週の行モード、キャンセル表示）は別キー `houmon_schedule_ui` に保存する。読めなくても既定値で動く。

## マスタ画面（利用者・スタッフ・訪問計画・休日）

上部タブ「マスタ」の中で切り替える。一覧は名前で検索でき、「無効も表示」で無効化した行も出す。行をクリックすると編集モーダル、「＋ 追加」で新規モーダルが開く。マスタは物理削除せず「無効にする」「有効に戻す」で切り替える。

| 画面 | 一覧の列 | 編集できる項目 |
|---|---|---|
| 利用者 | 表示名、保険・要介護度、指示書の期限（30日以内は黄、切れていれば赤）、契約期間、今日の状態、計画数、今後の予定数、エリア | 基本（氏名・ふりがな・表示名・管理番号・保険種別・要介護度・精神科・公費・別表7/8・ケアマネ・医療機関・エリア）、指示書（複数行）、契約期間、状態期間（入院・休止・終了。複数行）、要件（2名訪問・対応可能職種）、希望（希望担当・NG担当・希望時間帯・NG時間帯・備考）、備考 |
| スタッフ | 表示名（色付き）、職種、雇用、勤務可能枠の要約、在籍期間、今後の予定数、領域 | 基本（氏名・表示名・職種・雇用形態・移動手段・表示色・在籍期間）、領域（精神科・小児・ターミナル＋自由タグ）、勤務可能枠（曜日ごとの複数行。「平日 8:30〜17:30 をセット」ボタンあり）、備考 |
| 訪問計画 | 利用者、曜日・時刻・所要、種別、担当、繰り返し、有効期間、問題（`checkPlanRules` の結果） | 利用者、種別、曜日、開始時刻、所要時間（終了時刻を自動表示）、担当1・2、繰り返し（毎週／隔週＋基準日／第N週）、有効期間、備考。「当月の展開日を確認」で保存前に展開される日と見送り理由を表示 |
| 休日 | 日付、名称、種別 | 追加（日付・名称・祝日／事業所休業日）と削除。「祝日は計画の展開から除外する」の設定 |

- 無効化の確認ダイアログには、今後の予定数と計画数を表示する。無効化しても既存の予定・計画は残り、計画の展開と新しい割当だけが止まる。
- 保存の流れは訪問と同じ。項目の検証に通らなければ保存せず、項目名付きのメッセージを出す。行のある項目は「指示書 2行目 › 終了日: …」のように行番号を示す。
- 行を増減できる入力（指示書・状態期間・時間帯・勤務可能枠）は `data-f` 属性で読み取る。行の削除は保存するまで確定しない。

## 次の段階

1. 設定画面: 営業曜日、時間軸、入力刻み、既定所要時間、週の開始曜日、事業所名。
2. ルール層の拡張: 医療保険の週3日制限、介護の計画回数、移動時間の確保（ソフト警告）。
3. 出力: 利用者別の月間予定表、スタッフ別の日課表、CSV。祝日の一括登録。
4. ②勤務表との連携: `staff.availability` を日別の勤務データで上書きする取り込み口。これが入ったら勤務枠外をブロックに切り替える。
