# 訪問スケジュール データ構造 v1

単一HTML（`訪問スケジュール.html`）に内蔵するデータ層の仕様。画面はまだ無く、HTMLを開くとこの仕様どおりに動くかのセルフテストが走る。

## 方針

- 保存先は `localStorage` の1キー `houmon_schedule_db`。中身は1つのJSON。
- 日付は `YYYY-MM-DD`、時刻は `HH:MM`（24時間、`24:00` は終了時刻のみ可）。内部では必ずこの形式に正規化する。
- マスタ（利用者・スタッフ・計画）は物理削除せず `archived: true` で隠す。過去月の訪問が壊れない。
- 他レコードへの参照は名前でなく `id` で持つ。保存前に参照整合性を検証し、通らないデータは保存しない。
- 個人情報は最小限。被保険者番号・住所の番地・電話は持たない。表示には `displayName`（略称）を優先する。
- サンプルデータは架空の「利用者A」「看護 太郎」のみ。実名は入れない。

## 全体（db）

| 項目 | 型 | 内容 |
|---|---|---|
| `schemaVersion` | 数値 | 現在 `1`。上げるときは `MIGRATIONS` に変換手順を追加する |
| `meta` | object | `createdAt` / `updatedAt`（ISO文字列）/ `stationName` |
| `settings` | object | 下表 |
| `holidays` | Holiday[] | 祝日・事業所休業日 |
| `patients` | Patient[] | 利用者 |
| `staff` | Staff[] | スタッフ |
| `plans` | Plan[] | 訪問計画（週パターン） |
| `visits` | Visit[] | 訪問（個別の予定・実績） |
| `history` | HistoryEntry[] | 変更履歴。上限300件で古いものから捨てる |

### settings

| 項目 | 既定 | 内容 |
|---|---|---|
| `businessDows` | `[1,2,3,4,5]` | 営業曜日（0=日） |
| `dayStart` / `dayEnd` | `08:00` / `20:00` | 画面の時間軸 |
| `slotMin` | `15` | 時刻入力の刻み（5/10/15/30/60） |
| `defaultDurationMin` | `60` | 新規訪問の既定所要時間 |

## Patient（利用者）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `p_` で始まる |
| `code` | string | | 事業所内の管理番号（保険番号は使わない） |
| `name` / `nameKana` | string | 名のみ○ | 氏名 |
| `displayName` | string | | 画面・印刷用の略称。空なら `name` |
| `insurance` | enum | ○ | `iryo` 医療 / `kaigo` 介護 |
| `careLevel` | enum | ○ | `none` / `yoshien1-2` / `yokaigo1-5`。介護保険なら `none` 不可 |
| `psychiatric` | bool | ○ | 精神科訪問看護 |
| `publicExpense` | bool | ○ | 公費あり |
| `specialFlags` | object | ○ | `betsu7` / `betsu8`（別表7・8） |
| `instructions` | Instruction[] | | 指示書。`{ id, type, from, to, note }`。`type` は `normal` / `special` / `psychiatric` / `psychiatricSpecial`。`from` `to` は必須 |
| `careManager` / `hospital` | string | | 担当ケアマネ・主治医の医療機関（表示用） |
| `area` | string | | 訪問エリア（町名程度） |
| `requirements` | object | ○ | `needsTwoStaff`（2名訪問必須）/ `allowedRoles`（対応可能職種。空=制限なし） |
| `preferences` | object | ○ | `preferredTimeRanges` / `ngTimeRanges`（`{ dow, start, end }`、`dow` null=全曜日）/ `preferredStaffIds` / `ngStaffIds` / `note`。希望とNGに同じスタッフは不可 |
| `contract` | object | ○ | `start` / `end`。`end` null=継続中。契約外の日は状態 `ended` |
| `statusPeriods` | object[] | ○ | `{ status, from, to, note }`。`status` は `hospitalized` / `suspended` / `ended`（`active` は登録しない）。期間同士の重なり不可 |
| `archived` | bool | ○ | 無効化 |
| `note` | string | | |
| `createdAt` / `updatedAt` | string | ○ | ISO |

ある日の利用者の状態は `derive.patientStatusOn(p, date)` で求める。契約外なら `ended`、`statusPeriods` に該当があればその状態、なければ `active`。

## Staff（スタッフ）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `s_` で始まる |
| `name` / `displayName` | string | 名のみ○ | |
| `role` | enum | ○ | `NS` 看護師 / `LPN` 准看護師 / `PT` / `OT` / `ST` / `OTHER` |
| `employment` | enum | ○ | `fulltime` / `parttime` |
| `skills` | string[] | ○ | `psychiatric` `pediatric` `terminal` など自由タグ |
| `transport` | enum | ○ | `car` / `bike` / `walk` |
| `color` | string | ○ | `#rrggbb` |
| `availability` | object[] | ○ | 標準の勤務可能枠 `{ dow, start, end }`。②勤務表ができたら日別データで上書きする |
| `employmentPeriod` | object | ○ | `start` / `end`。在籍期間外は割当不可 |
| `archived` / `note` / `createdAt` / `updatedAt` | | | Patient と同じ |

サービス種別と担当できる職種は `ROLE_SERVICE` で固定。看護=`NS`,`LPN`、リハビリ=`PT`,`OT`,`ST`。2名訪問の2人目はこの制限を受けない（その他職員の同行を許す）。

## Plan（訪問計画・週パターン）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `pl_` で始まる |
| `patientId` | string | ○ | |
| `serviceType` | enum | ○ | `nursing` / `rehab` |
| `durationMin` | 整数 | ○ | 1〜600。開始＋所要が翌日にまたがる値は不可 |
| `dow` | 0〜6 | ○ | 曜日 |
| `start` | HH:MM | ○ | |
| `staffIds` | string[] | ○ | 既定の担当 0〜2名。空なら未割当で展開 |
| `recurrence` | object | ○ | `kind`: `weekly` 毎週 / `biweekly` 隔週（`anchorDate` 必須。基準日以降で最初にその曜日になる日を起点に2週おき）/ `weeksOfMonth` 第N週（`weeksOfMonth: [1,3]` など 1〜5） |
| `period` | object | ○ | `from` / `to`。計画の有効期間 |
| `archived` / `note` / `createdAt` / `updatedAt` | | | |

`rules.expandPlan(db, plan, year, month)` が月展開を行い、`{ visits, skipped }` を返す。`visits` は未保存の Visit。`skipped` は見送った日と理由（`patientStatus` 入院等 / `holiday` 休日 / `exists` 展開済み）。休日に当たった回は画面側で振替候補として扱う。

## Visit（訪問）

| 項目 | 型 | 必須 | 内容 |
|---|---|---|---|
| `id` | string | ○ | `v_` で始まる |
| `date` | YYYY-MM-DD | ○ | |
| `start` / `end` | HH:MM | ○ | `end` > `start`。日またぎ不可 |
| `patientId` | string | ○ | |
| `staffIds` | string[] | ○ | 0〜2名、重複不可。2名=複数名訪問 |
| `serviceType` | enum | ○ | `nursing` / `rehab` |
| `planId` | string/null | | 計画から展開した場合の元計画。`origin: plan` なら必須 |
| `origin` | enum | ○ | `plan` 計画から展開 / `manual` 手入力 / `transfer` 振替 |
| `status` | enum | ○ | `planned` 予定 / `confirmed` 確定 / `done` 実施 / `cancelled` キャンセル / `transferred` 振替元 |
| `cancelReason` | enum/null | 条件付 | `cancelled` のとき必須、それ以外は null。`patient` / `hospital` / `office` / `weather` / `holiday` / `other` |
| `transferredToId` | string/null | 条件付 | `transferred` のとき必須（振替先） |
| `transferredFromId` | string/null | 条件付 | `origin: transfer` のとき必須（振替元）。振替元と振替先は互いに参照し合う。片方だけでは検証エラー |
| `flags` | object | ○ | `emergency` 緊急訪問 / `training` 研修同行（複数名加算の対象外） |
| `actual` | object/null | 条件付 | `{ start, end }`。`done` のとき必須 |
| `note` / `createdAt` / `updatedAt` | | | |

保存しない派生値: 所要時間、時間帯区分（開始時刻で判定。22:00〜06:00 深夜、06:00〜08:00 と 18:00〜22:00 夜間・早朝、それ以外 日中）、長時間（90分超）、複数名（2名かつ研修でない）。加算判定はこれらから後工程で行う。

### ステータス遷移

| 現在 | 変更できる先 |
|---|---|
| planned | confirmed, done, cancelled, transferred |
| confirmed | planned, done, cancelled, transferred |
| done | confirmed（実施の取り消し） |
| cancelled | planned（キャンセルの取り消し） |
| transferred | なし（戻すには振替先を削除する） |

遷移は `rules.changeVisitStatus` と `repo.visits.setStatus` だけが行う。表に無い遷移は例外になる。

### 振替

`repo.visits.transfer(db, id, { date, start, end?, staffIds? })` が、元を `transferred` にし、新しい訪問を `origin: transfer` で追加し、双方向参照を同時に作る。振替で参照されている訪問は `remove` できない。

## Holiday（休日）

`{ date, name, kind }`。`kind` は `national` 祝日 / `office` 事業所休業日。同じ日付・種別の重複は不可。

## HistoryEntry（変更履歴）

`{ at, action, entity, entityId, before?, after? }`。`action` は `add` / `update` / `status` / `transfer` / `remove`。リポジトリ経由の変更が自動で積まれる。

## ハード制約チェック

`rules.checkVisitRules(db, visit)` が `[{ code, msg }]` を返す。空なら保存可。画面側はこれをブロック条件に使う。

| code | 内容 |
|---|---|
| `patientStatus` | 利用者がその日 active でない（入院・休止・契約外） |
| `noInstruction` | その日に有効な指示書がない |
| `roleMismatch` | 1人目の担当の職種がサービス種別に合わない |
| `staffUnavailable` | 担当がその時間帯に勤務可能枠を持たない、または在籍期間外 |
| `ngStaff` | 利用者のNG担当 |
| `roleNotAllowed` | 利用者の対応可能職種に含まれない |
| `needsTwoStaff` | 2名訪問必須なのに1名以下 |
| `staffOverlap` | 担当が同日同時刻に別の訪問を持つ（キャンセル・振替元は除く） |
| `patientOverlap` | 利用者が同日同時刻に別の訪問を持つ |

医療保険の週3日制限や介護の計画回数超過は、月単位の集計が必要なので次の段階（ルール層の拡張）で足す。

## 保存・読込

- `store.load(localStorage)` → `{ db, errors, fresh, backupKey }`。保存が無ければ空DB。JSONが壊れていれば消さずに `houmon_schedule_db_broken_<時刻>` へ退避して空DBで起動し、`errors` に理由を入れる。
- `store.save(db, localStorage)` → 検証に通らなければ保存せず `{ ok: false, errors }`。通れば `updatedAt` を更新して保存。4MBを超えると `warn` を返す。
- `store.parseDb(text)` → ファイル読込用。移行と検証を通した結果を返す。
- `store.migrate(raw)` → `schemaVersion` が古ければ順に変換、新しければ例外。欠けた配列や設定は既定値で補う。

## 公開API（`window.VS`）

| 名前空間 | 内容 |
|---|---|
| `VS.ENUMS` / `ROLE_SERVICE` / `STATUS_TRANSITIONS` | 列挙と固定ルール |
| `VS.date` / `VS.time` | 日付・時刻ユーティリティ |
| `VS.create` | 既定値入りの新規オブジェクト生成 |
| `VS.validate` | 各エンティティと DB 全体の検証 |
| `VS.derive` | 派生値と日別の判定 |
| `VS.rules` | 重複検出・制約チェック・ステータス遷移・計画展開 |
| `VS.repo` | 追加・更新・無効化・振替・削除（履歴付き） |
| `VS.store` | 保存・読込・移行・書き出し |
| `VS.sample.build(year, month)` | 架空のサンプルDB |

画面側は DOM だけを扱い、データの変更は必ず `VS.repo` と `VS.store` を通す。

## テスト

HTMLを開くと「2. セルフテスト」に結果が出る。Node でも同じテストを実行できる。

```bash
python3 - <<'PY'
import re, pathlib
h = pathlib.Path("訪問スケジュール/訪問スケジュール.html").read_text(encoding="utf-8")
js = "".join(re.search(r'^<script id="%s">\n(.*?)^</script>' % s, h, re.S | re.M).group(1) for s in ("vs-data", "vs-tests"))
js += "\nconst r = VS_TESTS.run(); r.forEach(x => console.log((x.ok ? 'PASS ' : 'FAIL ') + x.name, x.detail)); process.exit(r.some(x => !x.ok) ? 1 : 0);"
pathlib.Path("/tmp/vs_test.js").write_text(js, encoding="utf-8")
PY
node /tmp/vs_test.js
```
