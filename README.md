# クリケア訪問看護ステーション ホームページ

STUDIO で制作されていたホームページ（https://giveandmake-c.com）を、
**見た目そのままに**、自分たちで編集・保守できる形で作り直したものです。

- 特別なソフトのインストールは不要（Mac に最初から入っている Python だけで動きます）
- 文章・画像・ブログはすべて `content/` フォルダのファイル
- 月額費用のかかるサービスに縛られません

---

## 1. まずはこれだけ覚えてください

デスクトップの `kuricare-site` フォルダの中に、ダブルクリックするだけのアイコンが4つあります。

| アイコン | いつ使うか |
|---|---|
| **① 編集をはじめる** | 文章・写真・ブログを編集する（いちばんよく使います） |
| **② ホームページを見る** | できあがりだけ確認する |
| **③ 点検する** | 月1回。リンク切れや写真の抜けを自動チェック |
| **④ バックアップを取る** | 月1回。まちがえたときに戻せるよう保存 |

画面写真つきの操作ガイドは、同じフォルダの `使い方ガイド.html` をダブルクリックすると開きます。

ターミナルから使う場合は、フォルダに移動してからコマンドを実行します。

```bash
cd ~/Desktop/kuricare-site
```

| やりたいこと | コマンド |
|---|---|
| 編集する | `python3 admin/server.py` |
| 見た目を確認する | `python3 build.py --serve` |
| 点検する | `python3 tools/check.py` |

## 2. 管理画面で編集する（いちばん簡単な方法）

デスクトップの `kuricare-site` フォルダにある **`① 編集をはじめる`** をダブルクリックします。
（ターミナルから起動する場合は `python3 admin/server.py`）

ブラウザが自動で開きます（開かないときは http://localhost:8080 ）。

### 画面の見かた

左側のメニューから、直したいものを選びます。

| メニュー | 内容 |
|---|---|
| ページ | トップ・サービス内容・会社概要・スタッフ紹介など、固定ページの文言と写真 |
| 記事 | ブログ（95件）と採用情報（4件）の作成・編集・削除 |
| 画像ライブラリ | 写真・イラストの一覧、アップロード、削除 |
| サイト全体の設定 | ロゴ・会社情報・電話番号・SNSリンク・メニュー・下部の案内欄 |
| 点検する | リンク切れや画像欠けの自動チェック |

編集画面は見出しごとに折りたためます。直したい見出しをクリックして開いてください。
入力後、画面下の **「保存する」** を押すと、その場でサイトに反映されます。

### 写真・イラストの差し替え

画像の項目には、いまの写真とボタンが並んでいます。

- **「画像を選ぶ」** … 手持ちの画像から選びます。開いた画面の右上から、その場でパソコンの写真をアップロードすることもできます
- **「外す」** … 画像を空にします
- 複数枚並ぶ項目（トップのスタッフ写真など）は、**←→** で並べ替え、**✕** で外し、**＋追加** で増やせます
- ブログ本文では **「本文に画像を入れる」** ボタンで、カーソル位置に写真を挿入できます
- 画像ライブラリ画面では、ドラッグ＆ドロップでまとめてアップロードできます

### 項目の追加・削除

スタッフ・よくある質問・会社情報の表など、同じ形が並ぶ部分は
**「＋ 〇〇を追加」** で増やし、各項目の **削除** で減らせます。**↑↓** で順番も変えられます。

### 文字の色と改行

トップページのキャッチコピーなど、色をつけられる項目では次のように書きます。

- 改行したいところで **Enter** を押す
- オレンジ色にしたい文字は `[[ ]]` で囲む（例：`[[確かな看護]]と`）

## 3. Claude Code で編集する

「トップページのキャッチコピーを変えて」「ブログを1本追加して」のように話しかければ編集できます。
指示するときに、下のフォルダ構成を伝えると確実です。

```
kuricare-site/
├ content/              ← 文章・記事はすべてここ
│  ├ site.json          … 会社情報・ヘッダー・フッター・CTA（全ページ共通）
│  ├ pages/*.json       … 各ページの文言
│  ├ blog/*.md          … ブログ記事（95本）
│  └ recruit/*.md       … 求人記事（4本）
├ assets/               ← 画像・CSS・JS
│  ├ images/            … 写真・イラスト（479点）
│  ├ css/style.css      … デザイン（色・文字・余白）
│  └ js/main.js         … メニュー開閉など
├ templates/*.html      ← ページの骨組み
├ build.py              ← サイトを生成するプログラム
├ admin/server.py       ← 管理画面
├ tools/                ← 点検・バックアップ・比較ツール
└ dist/                 ← 生成結果（公開するのはこのフォルダ）
```

## 4. ブログ記事の書き方

`content/blog/` に `2026-08-20-なんとか.md` という名前でファイルを作ります。

```markdown
---
title: "記事のタイトル"
slug: "url-name"
date: "2026-08-20"
thumbnail: "/assets/images/写真.webp"
description: "検索結果に出る短い説明"
---

本文をここに書きます。
改行はそのまま改行になります。

## 見出し

- 箇条書き
- 箇条書き

![](/assets/images/写真2.webp)

[リンクの文字](https://example.com)
```

`date` の新しい順に並びます。公開URLは `/blog/<slug>/` です。

## 5. フォームの送信先を設定する（重要）

STUDIO のフォーム機能は使えなくなるため、**お問い合わせフォームと見学申込フォームは
現在まだ送信できません**。Google フォームにつなぐと送信できるようになります。

### 手順

1. Google フォームで、サイトと同じ項目のフォームを作ります。
   - お問い合わせ用: お名前／電話番号／メールアドレス／お問い合わせ項目／その他お問い合わせ内容
   - 見学応募用: お名前／E-mail／希望求人／希望内容／希望事業所／電話番号／その他ご相談やご質問
2. フォームの「プレビュー（目のアイコン）」を開き、
   ページ上で右クリック →「ページのソースを表示」。
3. `entry.123456789` のような文字列を探し、どの項目がどの番号か控えます。
4. `content/pages/contact.json` と `entry.json` の `google_form` を書き換えます。

```json
"google_form": {
  "mode": "native",
  "action": "https://docs.google.com/forms/d/e/フォームID/formResponse",
  "embed_url": "",
  "entries": {
    "name": "entry.123456789",
    "tel": "entry.234567890",
    "email": "entry.345678901",
    "topic": "entry.456789012",
    "message": "entry.567890123"
  }
}
```

5. `python3 build.py` を実行すれば完了です。**見た目は今のまま**で、
   送信内容が Google スプレッドシートに溜まります。

### かんたんに済ませたい場合

デザインは Google フォームのものになりますが、`embed_url` に
Google フォームの埋め込みURL（`.../viewform?embedded=true`）を入れるだけでも動きます。
その場合 `action` と `entries` は空のままで構いません。

## 6. 定期的な保守点検

| 頻度 | コマンド | 内容 |
|---|---|---|
| 編集のたび | `python3 tools/check.py` | リンク切れ・画像欠け・記事の書式ミスを確認 |
| 編集のたび | `python3 tools/check_mobile.py` | スマホ・タブレット表示の崩れを確認（Chrome が必要） |
| 月1回 | `python3 tools/check.py --external` | 外部リンク（Amazon・厚労省など）の生存確認 |
| 月1回 | `python3 tools/backup.py` | `backups/` に日付つきZIPを保存（20世代まで自動保持） |
| 移行の確認時 | `python3 tools/compare_live.py` | 公開中のSTUDIOサイトと文章を比較し、取り込み漏れを検出 |

`check.py` は問題があれば終了コード 1 を返すので、自動実行にも使えます。

## 7. 他のパソコンと共有する

このサイトは「フォルダごと持ち運べる」つくりです。特別なインストールは要りません。

### 相手のパソコンに必要なもの

| | 必要なもの |
|---|---|
| **Mac** | 何も要りません（Python が最初から入っています） |
| **Windows** | Microsoft Store から「Python 3」をインストール（無料・5分程度） |

### Windows で使う

`Windows用` フォルダに、Mac の `.command` と同じ働きをする `.bat` を用意しています。

| ファイル | 内容 |
|---|---|
| `① 編集をはじめる.bat` | 編集画面を開く（起動中でも自動で入れ替わります） |
| `② ホームページを見る.bat` | プレビュー（すでに開いていればそれを表示） |
| `③ 点検する.bat` | リンク切れ・画像欠け＋スマホ表示のチェック |
| `④ バックアップを取る.bat` | 日付つきZIPを `backups/` に保存 |
| `⑤ 共有用にまとめる.bat` | 配布用ZIPをデスクトップに作成 |
| `⑥ 変更をGitHubに送る.bat` | 点検してGitHubへ送信・自動公開 |
| `_python.bat` | 内部で使う共通処理（ダブルクリック不要） |
| `はじめにお読みください.txt` | Windows向けの説明 |

- Python が入っていない場合は、`.bat` を実行するとインストール手順が表示されます
- `⑥` は `git` を自動で探します。PATH に無い場合は GitHub Desktop に同梱されている git を使います
- 「WindowsによってPCが保護されました」と出たら「詳細情報」→「実行」

### 方法A：1回だけ渡す（かんたん）

**`⑤ 共有用にまとめる`** をダブルクリックすると、デスクトップに
`kuricare-site_共有用_日付.zip`（約40MB）ができます。

これを AirDrop・USBメモリ・ギガファイル便などで渡してください。
受け取った人は ZIP を展開してデスクトップに置き、

- Mac → `① 編集をはじめる.command`
- Windows → `Windows用` フォルダの `① 編集をはじめる.bat`

をダブルクリックすれば、そのまま編集できます。

> 生成物（`dist`）やバックアップは自動で除かれるので軽くなります。相手の環境で自動的に作り直されます。

### 方法B：いつも最新を全員で共有する（事業所内でおすすめ）

`kuricare-site` フォルダごと **OneDrive / Google ドライブ / Dropbox の共有フォルダ** に置きます。
以後、誰が編集しても全員のパソコンに反映されます。

**注意点**

- **同時に編集しない**でください。2人が同時に「保存する」を押すと、片方の変更が消えることがあります。「いまから触ります」と一声かけるルールにしておくと安全です。
- OneDrive の場合、フォルダを右クリック →「**このデバイス上で常に保持する**」にしてください。クラウド上だけに置かれていると起動できません。
- `dist` と `backups` フォルダは同期しなくて構いません（容量を食うだけです）。

### 方法C：GitHub で管理する（公開の自動化つき・おすすめ）

複数人でしっかり管理したい、公開も自動化したい場合はこちらです。
一度設定すれば、**編集 →「⑥ 変更をGitHubに送る」→ 1〜2分でホームページが自動更新**になります。

準備はすべて済んでいます。

- `.gitignore` … 送らなくてよいファイルの設定
- `.github/workflows/deploy.yml` … 自動で作り直して公開する設定
- `⑥ 変更をGitHubに送る.command` … 点検してからGitHubへ送るボタン

**手順は `GitHub公開の手順.html` をダブルクリックしてご覧ください。**
（GitHubアカウント作成 → GitHub Desktop導入 → 公開設定、の3ステップです）

かんたんにまとめると:

1. github.com でアカウントを作る
2. GitHub Desktop をインストールしてログイン
3. `File` → `Add Local Repository` で `kuricare-site` を選ぶ
4. `Commit to main` → `Publish repository`
   （リポジトリ名は必ず **`ユーザー名.github.io`**、**Public** で）
5. GitHubの `Settings` → `Pages` → Source を **GitHub Actions** に変更
6. 2〜3分で `https://ユーザー名.github.io/` に公開される

独自ドメイン `giveandmake-c.com` への切り替えは、しばらく様子を見てからで大丈夫です。

### どれを選べばよいか

| 状況 | おすすめ |
|---|---|
| ひとまず別のパソコンでも触ってみたい | 方法A |
| 事業所の数台で、いつも最新を共有したい | 方法B |
| 複数人で管理し、公開まで自動化したい | 方法C |

## 8. 公開する

`dist/` フォルダの中身をそのままアップロードすれば公開できます。
サーバー側の特別な設定は不要です（PHPやデータベースは使いません）。

**おすすめ: Cloudflare Pages または Netlify**（どちらも無料枠で足ります）

1. このフォルダを GitHub にアップロード
2. Cloudflare Pages で「ビルドコマンド `python3 build.py`」「出力先 `dist`」を指定
3. 独自ドメイン `giveandmake-c.com` を設定

> ドメインを切り替える前に、STUDIO 側は解約せずに残しておくと安全です。
> 切り替え後しばらく様子を見て、問題がなければ解約してください。

**サーバーにFTPでアップロードする場合**は、`dist/` の中身を公開フォルダにコピーするだけです。

## 9. スマートフォン・タブレット表示について

パソコン・タブレット・スマートフォンのどの画面幅でも崩れないよう作ってあります。

| 画面幅 | 表示 |
|---|---|
| 1141px 以上 | パソコン向け（メニュー横並び・2カラム） |
| 841〜1140px | 余白を詰めたパソコン向け |
| 541〜840px | タブレット向け（メニューがハンバーガーに・1カラム） |
| 540px 以下 | スマートフォン向け（文字と余白を調整） |

**指で押す部分は 44px 以上**を確保しています（ハンバーガーメニュー、フッターのリンク、SNSアイコン、ラジオボタン、同意リンクなど）。

会社概要ページの電話番号は、**スマートフォンではタップすると発信**できます。

`python3 tools/check_mobile.py`（または `③ 点検する`）を実行すると、
主要12ページを 320 / 375 / 390 / 768 / 1024px の5種類の画面幅で自動チェックします。

## 10. デザインを変えたいとき

`assets/css/style.css` の先頭にある変数を書き換えると、サイト全体に反映されます。

```css
:root {
  --c-orange: #ed7300;   /* メインのオレンジ */
  --c-brown:  #695544;   /* ナビの文字色 */
  --c-bg:     #fbf7ef;   /* 薄いベージュの背景 */
  --container: 1200px;   /* 本文の横幅 */
  --section-gap: 120px;  /* セクションの上下余白 */
}
```

書体は Montserrat（英字見出し）／Noto Sans JP（小見出し）／Zen Maru Gothic（本文）で、
元サイトと同じ設定です。

## 11. 元サイトから引き継いだもの・変えたもの

**そのまま引き継いだもの**

- 全11ページの構成・文章・写真・イラスト
- ブログ95本、求人4本（本文・写真・日付・URLのslugすべて）
- 配色、書体、レイアウト、URL構造（`/blog/xxxx` などのアドレスが変わりません）

**変えたもの**

| 項目 | 変更内容 | 理由 |
|---|---|---|
| フォーム | Google フォーム連携に変更（要設定） | STUDIO のフォーム機能が使えないため |
| アニメーション | スクロール時のふわっと出る演出を省略 | 表示速度と保守しやすさを優先 |
| ブログ一覧 | 「もっと見る」を廃止し全件表示 | 記事を探しやすくするため |
| 装飾用の小イラスト | 一部未配置 | `tools/check.py` の「未使用」に出ている画像です。必要なら追加できます |

## 12. 困ったとき

- **ビルドでエラーが出る** … だいたい JSON のカンマ抜けです。`python3 tools/check.py` が場所を教えてくれます。
- **編集内容が反映されない** … `python3 build.py` を実行し忘れていないか確認してください。管理画面から保存した場合は自動で実行されます。
- **元に戻したい** … `backups/` の ZIP を展開して `content/` を差し替えてください。
- **それでも分からない** … Claude Code に「`kuricare-site` でこういうエラーが出た」と伝えてください。
