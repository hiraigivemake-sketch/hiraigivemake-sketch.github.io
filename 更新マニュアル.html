更新マニュアル

GitHubを使った更新のしかたを、順番どおりにまとめました。パソコン操作に慣れていなくても、このとおりに進めれば大丈夫です。

お使いのパソコン
を選ぶと、説明が切り替わります

まず、全体のしくみ

毎回の作業：4つのステップ

この4つだけです。慣れれば5分もかかりません。

1

最新の状態にする

GitHub Desktop を開き、上の Fetch origin を押す
→ Pull origin に変わったら、それも押す

他のパソコンでも編集している場合は、必ずやってください。これを忘れると、他の人の変更が消えてしまうことがあります。

1台のパソコンだけで使っている場合は、飛ばしても大丈夫です。

2

文章や写真を直す

① 編集をはじめる.command をダブルクリック Windows用 フォルダを開き、① 編集をはじめる.bat をダブルクリック

黒い画面が出たあと、ブラウザで編集画面がひらきます。黒い画面は閉じずにそのままにしてください。

左のメニューから直したいものを選び、書きかえたら画面下の 保存する を押します。

※ 「WindowsによってPCが保護されました」と出たら 詳細情報 → 実行 を押します（初回だけ）。

3

できあがりを確認する

編集画面の右上 サイトを見る を押す

実際のホームページの見た目で確認できます。おかしければ編集画面に戻って直せば大丈夫です。この時点ではまだ、インターネット上のホームページは変わっていません。

確認できたら、ブラウザと黒い画面を閉じます。

4

GitHubに送って公開する

⑥ 変更をGitHubに送る.command をダブルクリック Windows用 フォルダの ⑥ 変更をGitHubに送る.bat をダブルクリック

黒い画面に 「✅ 送信しました」 と出れば成功です。1〜2分後にホームページが新しくなります。

送る前に自動で点検されるので、リンク切れなどがあれば送信は止まります。壊れたものが公開される心配はありません。

迷ったら。ステップ4まで進んでいなければ、インターネット上のホームページは何も変わりません。編集画面でいくら触っても大丈夫なので、安心して練習してください。

場面ごとのやりかた

ブログを1本書く

  1. 編集画面の左メニュー ブログ をクリック
  2. ＋ 新しく追加 を押す
  3. タイトル・日付を入れる
  4. サムネイル画像の 画像を選ぶ で写真を選ぶ（右上からパソコンの写真もアップロードできます）
  5. 本文を書く。写真を入れたい場所で 本文に画像を入れる を押す
  6. 下の 保存する → 確認 → ステップ4（⑥を押す）

写真・イラストを差し替える

  1. 左メニューから直したいページを選ぶ
  2. 写真の横の 画像を選ぶ を押す
  3. 一覧から選ぶ。新しい写真を使うなら、開いた画面の右上 パソコンからアップロード
  4. 保存する → 確認 → ステップ4（⑥を押す）

スタッフを1人増やす

  1. 左メニュー スタッフ紹介 をクリック
  2. 「スタッフ」の見出しを開き、いちばん下の ＋ スタッフを追加 を押す
  3. 空のカードができるので、名前・写真・紹介文を入れる
  4. 順番は ↑ ↓ で変えられます
  5. 保存する → 確認 → ステップ4（⑥を押す）

Claude Code に直してもらったあと

やることは同じです。ステップ3（確認）→ ステップ4（⑥を押す）だけ行ってください。

どこが変わったか目で確かめたいときは、GitHub Desktop を開くと、左に変わったファイル、右に「赤＝消えた文字／緑＝増えた文字」が色分けで出ます。

2台目以降のパソコンで使う

はじめの準備（そのパソコンで1回だけ）

  1. Python を入れる（Windowsのみ）… Microsoft Store で「Python 3」を検索し、数字がいちばん大きいものを「入手」。設定は不要です
  2. GitHub Desktop を入れる … desktop.github.com から。同じアカウントでログイン
  3. フォルダを取り寄せる … メニュー File → Clone repository… → 一覧から hiraigivemake-sketch.github.io を選ぶ → 保存先をデスクトップにして Clone

ダウンロードが終わると、1台目とまったく同じフォルダができます。①〜⑥のファイルもそのまま入っています。「Windows用」フォルダの中に①〜⑥が入っています。

2台以上で使うときの、たった1つのルール

編集を始める前に、必ず GitHub Desktop で Fetch origin → Pull origin を押して最新にしてください（ステップ1）。

また、2人が同時に編集するのは避けてください。「いまから触ります」と一声かけるルールにしておくと安全です。

やってはいけないこと

これはNG理由
フォルダ名やファイル名を変えるボタンが動かなくなります
dist フォルダの中を直接直す自動で作り直されるため、次の保存で消えます
.git フォルダを消すGitHubとのつながりが切れます
2人が同時に編集する片方の変更が消えることがあります
フォルダを別の場所に移動するGitHub Desktop が見失います（移動したら再度 Add してください）

困ったとき

ダブルクリックしても何も起こらない
右クリック →「開く」を選び、確認画面でもう一度「開く」を押してください。Macの安全機能によるものです（初回だけ）。
「WindowsによってPCが保護されました」と青い画面が出ていませんか。詳細情報 → 実行 の順に押してください。
黒い画面に「Python が見つかりませんでした」と出た
画面に出ている手順どおり、Microsoft Store で「Python 3」をインストールしてください。5分ほどで終わります。終わったら、もう一度ダブルクリックします。
「点検で問題が見つかりました」と出て送信できない
壊れたものが公開されないよう、わざと止めています。黒い画面に何が問題か表示されているので、その文章をコピーして Claude Code に貼り付けてください。
「送信できませんでした」と出た
GitHub Desktop を開いて、上の Push origin を押してみてください。それでもだめなら、一度 Fetch origin → Pull origin をしてから、もう一度お試しください。
送信したのに、ホームページが変わらない
GitHubのサイトで Actions タブを開いてください。黄色い丸●なら作業中です（2〜3分待ちます）。緑のチェック✓なら完了しているので、ブラウザを再読み込み（⌘+RCtrl+F5）してください。赤い×なら Claude Code にご相談ください。
「Conflict」と出た
2人が同じ場所を同時に直したときに出ます。自分で直そうとせず、そのまま Claude Code に「GitHub Desktop で Conflict と出た」と伝えてください。
まちがえて公開してしまった
GitHub Desktop の History タブを開き、戻したい記録を右クリック → Revert changes in commit → 上の Push origin。1〜2分で元に戻ります。
黒い画面が閉じられない
ウィンドウの左上の赤い●右上の ×を押せば閉じられます。編集画面を開いている最中に閉じると編集画面も終了しますが、保存済みの内容は消えません。
